## 🔍 진단 (번들 직접 분석)

배포된 `layout` JS 청크를 까보니:
```js
function GoogleAnalytics(){ return c ? (...googletagmanager.../gtag/js?id=".concat(c)...) : null }
```
- `c` = 측정 ID 변수인데, **번들 어디에도 `G-XXXXXXXX` 값이 인라인돼 있지 않습니다** → `c`가 비어 있어 컴포넌트가 `null` 반환 = gtag 자체가 안 로드됨
- 게다가 번들에 `NEXT_PUBLIC_GA_MEASUREMENT_ID` 문자열이 그대로 남아 있습니다 → 빌드 시 이 변수가 **값으로 치환되지 않았다**는 결정적 증거

즉, 재배포는 됐지만 그 빌드가 환경변수 값을 못 받았습니다.

## 💡 원인 (가능성 순)

1. **빌드 캐시로 재배포** (가장 흔함) — Vercel "Redeploy" 시 기본 체크된 **"Use existing Build Cache"** 때문에 옛 빌드(ID 없는)가 재사용됨. `NEXT_PUBLIC_` 변수는 **빌드 시점에 코드에 박히므로**, 캐시 빌드로는 절대 안 들어갑니다.
2. **변수 이름 불일치** — 정확히 `NEXT_PUBLIC_GA_MEASUREMENT_ID`여야 함 (`NEXT_PUBLIC_` 접두사 빠지면 클라이언트에 노출 안 됨)
3. **환경(Environment) 누락** — **Production**에 체크 안 됨 (Preview만 설정 등)

## ✅ 해결 (차장님이 하실 것)

1. Vercel → Settings → Environment Variables에서 확인:
   - 이름: **`NEXT_PUBLIC_GA_MEASUREMENT_ID`** (철자 정확히)
   - 값: **`G-XXXXXXXXXX`**
   - Environment: **Production** 체크됨
2. **빌드 캐시 없이 재배포**: Deployments → 최근 배포 → `⋯` → **Redeploy** → **"Use existing Build Cache" 체크 해제** → Redeploy

## 📊 데이터가 Realtime에 들어가는 과정

```
누군가 사이트 접속
   ↓
① 브라우저가 페이지 로드 → GoogleAnalytics 컴포넌트 실행
   (단, 빌드에 G- ID가 있어야 실행됨 ← 지금 여기가 막혀 있음)
   ↓
② gtag.js 스크립트가 googletagmanager.com에서 로드
   ↓
③ gtag('config', 'G-XXX') + page_view 이벤트 발생
   ↓
④ 구글 수집 서버(google-analytics.com/g/collect)로 전송
   ↓
⑤ GA4 Realtime 리포트에 "활성 사용자 1명" + 이벤트 표시 (수 초~30초)
```

**Realtime은 "최근 30분간의 활동"만 보여줍니다.** 즉 **누군가 실제로 사이트에 들어가야** 데이터가 생깁니다. 가만히 있으면 아무것도 안 들어와요.

## ✅ 데이터 들어오게 하는 테스트 방법

1. 폰이나 PC 브라우저로 **https://glosource-ai.vercel.app/en** 직접 접속
2. GA4 → 보고서 → **실시간(Realtime)** 열기
3. **10~30초 안에** "지난 30분간 활성 사용자 1" 이 뜨면 성공 ✅
