**설계상 중요한 결정 3가지**

**CI에 진짜 비밀키를 안 넣습니다.** 빌드가 `DATABASE_URL`을 요구하길래 확인해 보니 *존재 여부만* 검사하는 모듈 스코프 체크였고, DB 의존 라우트는 전부 동적이라 빌드 중 쿼리가 0건입니다. 더미 값 3개로 빌드가 통과합니다. CI 산출물은 버려지고 Vercel이 진짜 env로 재빌드하므로 더미 값이 프로덕션에 닿을 수 없습니다 — 시크릿 38개를 GitHub에 복사할 필요가 없어졌습니다.

**집 PC가 아니라 클라우드에서 돕니다.** 없던 워커가 없다는 걸 아무도 몰랐던 이유가 바로 로컬이었기 때문입니다. PC가 꺼져 있어도 배포됩니다.

**Fast-forward 전용입니다.** 분기된 브랜치는 병합하지 않고 rebase 힌트와 함께 거부하고, 게이트를 우회하더라도 git 서버가 non-FF push를 거부합니다.

**⚠️ 솔직히 말씀드릴 것 — 첫 시도는 실패했습니다.** 워크플로를 도입한 커밋의 *본문에* 탈출구를 설명하려고 `[no-promote]`를 적었는데, 그게 탈출구 발동으로 읽혀서 **자기 자신의 배포를 건너뛰었습니다.** 자책골이지만 진짜 결함을 드러냈습니다 — 이 게이트를 문서화하거나 회고하는 커밋은 앞으로도 똑같이 조용히 배포 누락될 수 있었습니다. 제목 줄만 검사하도록 고쳤고, 그 과정에서 git의 `%s`가 "첫 줄"이 아니라 "첫 **문단**"이라 제목 뒤 빈 줄을 빠뜨리면 본문이 접혀 들어간다는 것도 발견해서 `%B | head -1`로 처리했습니다. 6개 케이스로 검증했습니다.

**앞으로 쓰실 때**
- 평소: 그냥 커밋하고 push → 알아서 배포
- 배포 원치 않을 때: 커밋 **제목**에 `[no-promote]` (본문 아님)
- 배포가 안 됐다 싶으면: GitHub Actions 실행 결과부터 확인
